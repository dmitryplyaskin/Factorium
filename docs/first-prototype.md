# Первый генератор производственных линий

## Использование

```powershell
cargo run --release -- extract
cargo run --release -- generate --product iron-gear-wheel --rate 5 --verify
```

`--product` — внутреннее имя предмета; `--rate` — требуемый выпуск в секунду.
В первом прототипе генерируется один рецепт с одним типом твёрдого ингредиента и
одним типом твёрдого продукта. Рецепт автоматически выбирается среди поддержанных
вариантов для выбранной машины. При неоднозначности требуется `--recipe`.

По умолчанию: assembling-machine-2, transport-belt, fast-inserter,
small-electric-pole, нормальное качество. Для плавки нужно указать электрическую
печь, например `--machine electric-furnace`. Рецепт в печи выбирает сама игра;
сборочному автомату рецепт записывается в блупринт.

Параметры: `--machine`, `--belt`, `--inserter`, `--pole`, `--catalog`, `--output`.
Для испытания: `--factorio`, `--mods`, `--builtin-only`, `--data-dir`, `--timeout`,
`--warmup` и `--measure` (последние два значения — игровые секунды). Переменные
`FACTORIO_BIN` и `FACTORIO_MOD_DIRECTORY` поддерживаются как при экспорте.

Без `--verify` игра для генерации не нужна; нужен ранее экспортированный каталог.
Модельная оценка не помечается как измеренная. `verify` повторно проверяет конечный
документ внутри `factory.json` и импортирует закодированную строку в движок:

```powershell
cargo run --release -- verify data/generated/factory.json
```

Если вручную изменён отдельный `blueprint.json`, это не меняет `factory.json`.
Для проверки изменённого проекта нужно обновить `document` внутри `factory.json`.
Проверяющий модуль не предназначен для произвольных сторонних блупринтов.

## Файлы результата

| Файл | Назначение |
| --- | --- |
| `blueprint.txt` | Готовая строка `0 + base64(zlib(JSON))` для импорта в Factorio |
| `blueprint.json` | Сущности, рецепты и явные медные провода формата Factorio 2.x |
| `factory.json` | Запрос, версия игры/модов, расчёты, ряды, порты, питание и конечный блупринт |
| `preview.svg` | Схематический вид: машины зелёные, ленты жёлтые, манипуляторы синие; провода и квадратные зоны питания |
| `verification.json` | Фактический выпуск, четыре окна измерений, электросети, незапитанные сущности и ошибки |

Новый экспорт проекта удаляет старый `verification.json`, чтобы прежняя успешная
проверка не сопровождала изменившийся чертёж. Неудача испытания сохраняет отчёт и
возвращает ненулевой код завершения CLI. Проекты хранятся в игнорируемом `data/`.

## Подача и размещение

Для цели `q` вычисляется теоретический ввод `q * ingredient_amount / product_amount`.
На практике предусмотрен запас 5%: сумма скоростей входных портов рассчитана на
выпуск `1.05*q`. Оба числа выводятся явно. Например, для 5 шестерёнок/с теоретически
нужно 10 пластин/с, а рекомендуемая подача в этом прототипе — 10,5 пластин/с.
Это режим «не ниже цели», а не точная синхронизация выпуска до заданной дроби.

Каждая машина обслуживается манипуляторами у краёв северной и южной сторон.
Положение и количество машин учитывают ширину/высоту из прототипов. Число машин
ограничивается скоростью крафта и консервативной оценкой манипуляторов; не только
временем рецепта. Размер руки явно установлен в 1, поэтому исследования вместимости
не требуются. Оценка учитывает скорости вращения/выдвижения и задержку подбора с ленты;
она намеренно оставляет запас, поэтому текущая раскладка не минимальна по числу машин.

Входная лента каждого ряда идёт с запада на восток над машинами. Выходная — под
ними, также на восток. Вход используется с обеих сторон; выходные манипуляторы
заполняют одну сторону. Лимит выхода поэтому составляет половину полной ёмкости
ленты; планирование дополнительно оставляет 15% запаса по лентам. Поток выше лимита
разбивается на несколько рядов с независимыми парами портов. Их ленты нужно подвести
отдельно: первый прототип не объединяет порты в общую внешнюю шину.

Порты содержат позицию крайнего тайла ленты, предмет, скорость и используемые стороны.
Вход подключается с запада к первому тайлу, выход продолжается на восток от последнего.
Проверяются физические соседства и достижимость collision box машины манипулятором.
Сильно отличающиеся placement footprint и collision box могут сделать шаблон
неприменимым; такой вариант отклоняется.

## Электроснабжение

Для выбранного типа столба из `quality_stats.normal` берутся:

- `supply_area_distance` — половина стороны квадратной зоны питания;
- `max_wire_distance` — максимальное расстояние между центрами соединённых столбов.

Это два независимых ограничения. Большая опора может передавать электричество далеко,
но питает небольшую область. Для неё может потребоваться больше опор, чем для средней.

Планировщик выбирает свободные места, покрывающие все электрические машины и
манипуляторы, затем соединяет острова покрытия, добавляя при необходимости промежуточные
столбы. Провода записываются явно, проверяются дальность, связность и максимум пять
медных соединений на столб. Наивное предположение «все потребители рядом со столбом,
значит всё подключено» не используется.

`power.connection_entity` и `power.connection_position` обозначают столб для внешнего
питания. Генератора электричества в пользовательском чертеже нет. Значение
`installed_power_watts` — консервативная оценка установленной нагрузки с учётом
idle drain; фактическое среднее потребление при неполной загрузке обычно ниже.
Размещение столбов выполняется эвристически и пока не минимизирует их число.

## Испытание в Factorio

Используется временный профиль с копией выбранного каталога модов и startup-настроек.
Сохранения и пользовательский профиль не изменяются.

Сценарий импортирует именно закодированную строку, строит призраки и оживляет их.
Проверяется количество сущностей, сохранение рецептов и ограничения руки манипулятора,
единая электросеть после импорта и наличие питания у всех потребителей.
Тестовый генератор подключается через единственный внешний столб к заявленному вводу.
Его автоматические провода удаляются: испытание не ремонтирует внутреннюю сеть.

Ресурс вводится только на входных тайлах с ограничением из портов; готовый продукт
извлекается только с выходных тайлов. Внутренние инвентари изначально пусты.
Рецепты разрешаются без исследования технологий, чтобы бонусы исследований не
изменяли скорость или продуктивность. Для реальной игры нужные рецепты и оборудование
должны быть открыты.

По умолчанию прогрев — 120 игровых секунд, измерение — ещё 120 секунд, четыре окна.
Проверяется средний выпуск не ниже цели и отсутствие значительного дрейфа скорости.
При менее чем 20 доставленных предметах результат отклоняется как недостаточный;
для медленных рецептов нужны более длительные `--warmup` и `--measure`.
Циклическая работа конечных буферов может требовать более длительных испытаний:
успешный конечный прогон не доказывает поведение в произвольном будущем окружении.

Совпадение версий игры/модов обязательно. Дополнительно сравниваются фактические
габариты оборудования, скорость ленты, параметры столба, скорость крафта,
состав/количества рецепта с продуктивностью и отсутствие порчи выбранных предметов.
Это обнаруживает существенные изменения startup-настроек даже без смены версии мода.

## Поддержка и ограничения

Поддерживаются электрические assembling-machine и furnace, обычные transport-belt,
электрические манипуляторы 1×1 с прямым вылетом в один тайл, столбы с поддерживаемой
геометрией. Данные читаются из каталога, названия рецептов не зашиты в алгоритм.
Встроенная продуктивность машины учитывается для разрешённой части детерминированного
выхода; модульные конфигурации и исследования продуктивности пока не задаются.

Пока отклоняются жидкости, несколько ингредиентов/продуктов, случайные количества
или вероятности, самовозврат, порча, ненормальные качества, длинные манипуляторы,
топливные машины и нестандартные механики. Генератор работает в условиях Nauvis и
проверяет ограничения поверхности. Модули/маяки не размещаются. Встроенные эффекты
качества и расхода энергии пока также отклоняются. Размеры, площадь поиска и количество
сущностей имеют защитные пределы, чтобы ошибочный запрос не создавал огромную фабрику.

## Проверки

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
cargo test --test generation_game --locked -- --ignored --nocapture
```

Обычные тесты не требуют игры. Они проверяют упаковку строки, детерминизм, баланс,
несколько рядов, прямоугольную машину 4×6, четыре типа столбов и отказ при повреждении
проводов, покрытия питания, направления манипуляторов, лент и размещения.

Интеграционный тест заново экспортирует текущую игру и измеряет девять конфигураций:
четыре столба на шестерёнках 5/с, многорядный выпуск 20/с, электрическую плавку,
провода с bulk-inserter, медленный манипулятор и, если установлен, electromagnetic-plant.
Дополнительно проверяется отказ при изменении скорости относительно каталога.
