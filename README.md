# Factorium

Генератор блупринтов для Factorio на Rust. Реализованы экспорт игровых прототипов
и первый генератор электрических линий для рецептов с одним твёрдым ингредиентом
и одним твёрдым продуктом: машины, ленты, манипуляторы и связанная сеть столбов.

## Веб-интерфейс

После экспорта каталога запустите:

```powershell
cargo run --release -- serve
```

Откройте [Factorium](http://127.0.0.1:3410). Выберите рецепт, скорость выпуска,
машину, ленту, манипулятор и столб, затем нажмите «Построить чертёж».
Схема показывает входы и выходы, электрические соединения и зоны питания.
Можно приблизить схему, выбрать отдельную сущность и запустить проверку
производительности в установленной Factorio.

Экспорт: строка импорта игры, TXT, JSON блупринта, SVG, полный проект и отчёт
проверки. Всё работает локально; Node.js и отдельная сборка фронтенда для запуска
не нужны. [Подробности и параметры запуска](docs/web-interface.md).

## Генерация первого блупринта

После экспорта каталога:

```powershell
cargo run --release -- generate --product iron-gear-wheel --rate 5 --verify
```

Команда создаёт `data/generated/blueprint.txt` для импорта в игру,
`blueprint.json`, `factory.json` с портами и расчётами, `preview.svg` с зоной
покрытия столбов и `verification.json` с результатом испытания. Проверено в игре:
цель 5 шестерёнок/с, измерено 5,25/с, одна электросеть, все потребители запитаны.

Можно выбрать оборудование:

```powershell
cargo run --release -- generate --product iron-plate --rate 2.5 --machine electric-furnace --pole big-electric-pole --verify --output data/smelting
cargo run --release -- generate --product copper-cable --rate 6 --belt fast-transport-belt --inserter bulk-inserter --pole substation --verify --output data/cables
```

Поддержаны малые/средние/большие столбы и подстанции. Площадь питания и максимальная
длина провода берутся отдельно из каталога. В чертеже нет генератора электричества:
подключите внешнее питание к указанному в выводе столбу. Несколько рядов имеют
несколько пар входных/выходных лент с одним типом предмета; координаты и скорости
каждого порта записаны в `factory.json`.

Без `--verify` выполняется статическая проверка, производительность остаётся
модельной оценкой. Повторная проверка готового проекта:

```powershell
cargo run --release -- verify data/generated/factory.json
```

Подробные возможности, ограничения и проверки: [первый прототип](docs/first-prototype.md).

## Требования

- Rust stable с Cargo, rustfmt и Clippy (`rust-toolchain.toml`).
- Для экспорта: установленная Factorio **2.1.24 или новее**. Проверено на 2.1.24
  под Windows с DLC Space Age, Quality, Elevated Rails и Recycler.
- Для чтения готового каталога и обычных тестов установка игры не нужна.

## Запуск

```powershell
cargo run --release -- extract
cargo run --release -- inspect
```

Экспортёр ищет игру в `FACTORIO_BIN`, `PATH` и стандартных каталогах Steam / Factorio
на Windows и Linux. По умолчанию CLI также ищет каталог пользовательских модов:
рядом с portable-установкой, в `%APPDATA%\Factorio\mods` или `~/.factorio/mods`.
Для нестандартной Steam-библиотеки, другого профиля или собственного конфига пути
нужно указать явно:

```powershell
cargo run --release -- extract --factorio "D:\SteamLibrary\steamapps\common\Factorio\bin\x64\factorio.exe" --mods "D:\FactorioProfile\mods" --output data/my-game
```

Доступны также `--data-dir`, `--timeout 300` (секунды на каждый процесс) и
`--builtin-only` (стандартный набор встроенных модов/DLC без пользовательского
профиля). `--builtin-only` не означает отключение DLC. Переменная
`FACTORIO_MOD_DIRECTORY` заменяет `--mods`. Все параметры: `cargo run -- extract --help`.

## Результат

В `data/game/` появляются:

- `catalog.json` — каталог с версией схемы, версией игры, активными модами и
  разрешёнными движком значениями, пригодный для чтения из Rust.
- `data-raw-dump.json` — полный `data.raw` после загрузки модов, без сокращений:
  все типы прототипов, включая графику, сигналы, оборудование и остальные данные,
  пока не вынесенные в отдельные Rust-модели.
- `dump.log`, `runtime.log` — логи двух запусков игры.

Экспорты исключены из Git. Повторный успешный экспорт заменяет файлы; каждый файл
записывается через временный файл и атомарную замену. Это не транзакция для всего
каталога: при ошибке диска между заменами часть файлов может быть от предыдущего
экспорта. Сообщения об ошибках игры содержат конец её лога; при превышении таймаута
дочерний процесс завершается.

В основном каталоге:

| Раздел | Данные |
| --- | --- |
| `recipes` | Все рецепты, включая скрытые и закрытые исследованием; категории, время, ингредиенты, продукты, температуры, вероятности, продуктивность, ограничения поверхности |
| `items` | Все подтипы предметов, размер стака, вес, топливо, модули, порча, ссылки на размещаемые здания и тайлы |
| `entities` | Все сущности; точные `tile_width` / `tile_height`, collision / selection box, маски коллизий, сетка, повороты, размещающие предметы |
| `entities` | Категории производства, фиксированные рецепты, скорость, слоты модулей, энергия, fluid boxes и соединения труб, конвейеры, манипуляторы, добыча, электроснабжение, логистика |
| `quality_stats` | Параметры сущностей и предметов для каждого зарегистрированного качества: скорость, энергия, радиусы, инвентари, порча и эффекты модулей |
| `fluids`, `technologies`, `tiles` | Температуры и теплоёмкость; исследования, их зависимости и эффекты; размещение и коллизии тайлов |
| `qualities`, `space_locations`, `surfaces`, `surface_properties` | Цепочки качеств, планеты и другие локации, свойства поверхностей |

Ключи разделов — внутренние имена Factorio, например `iron-plate` или
`assembling-machine-3`. Поля `localised_name` и `localised_description` содержат
локализационные структуры игры, а не переведённый текст. Ссылки на прототипы
представлены именами. Необязательные поля могут отсутствовать.

Единицы сохраняются из runtime API: размеры и координаты — в тайлах, `recipes.energy`
— секунды при скорости производства 1, энергия — джоули, мощность/расход энергии
— джоули за тик (для ватт умножить на 60), скорость ленты — тайлы за тик.
В Factorio 2.1 продукты имеют `independent_probability` и интервал
`shared_probability`; оба сохраняются, чтобы не потерять корреляцию результатов.
Размеры размещения берутся у движка, включая явные переопределения модов.

`enabled` у рецепта отражает начальное состояние прототипа. Доступность рецепта
в конкретном сохранении зависит от исследований; сохранения экспортёр не читает.
Каталог содержит определения, а не итоговые значения для конкретной постройки
с её модулями, маяками, исследованиями и окружением.

## API Rust

```rust
use std::path::Path;
use factorium::{ExtractOptions, discover_factorio, discover_mod_directory, extract_game_data};

fn main() -> anyhow::Result<()> {
    let binary = discover_factorio()?;
    let mut options = ExtractOptions::new(&binary);
    options.mod_directory = discover_mod_directory(&binary);
    let data = extract_game_data(&options, Path::new("data/game"))?;
    let assembler = &data.entities["assembling-machine-1"];
    assert_eq!((assembler.tile_width, assembler.tile_height), (3, 3));
    Ok(())
}
```

Готовый каталог: `GameData::from_reader(std::fs::File::open(path)?)?`.
Основные модели находятся в `src/model.rs`; дополнительные поля прототипов
сохраняются в `properties`, не теряя данные при сериализации.

## Как устроено извлечение

1. Создаётся временный профиль с отдельными `config.ini`, логами и `script-output`.
2. Выбранные моды целиком копируются, вместе с `mod-list.json` и `mod-settings.dat`.
   Поэтому учитываются настройки startup, распакованные моды и ZIP-архивы.
   Символические ссылки внутри каталога модов не поддерживаются.
3. Первый запуск Factorio выполняет `--dump-data`.
4. Второй запуск выполняет временный `--test-scenario`: `src/export.lua` читает
   runtime-прототипы, экспортирует каталог и завершает тест на первом тике.
5. Rust проверяет схему и каталог, затем сохраняет результат. Временный профиль удаляется.

Игровые сохранения и пользовательский профиль не изменяются. Для больших наборов
модов нужно место под их временную копию. Ошибка модов останавливает экспорт.
Версии 1.1 и 2.0 пока не поддерживаются: экспортёр использует API и тестовый режим 2.1.

Описание используемых API: [параметры запуска](https://wiki.factorio.com/Command_line_parameters),
[LuaPrototypes](https://lua-api.factorio.com/2.1.24/classes/LuaPrototypes.html),
[LuaEntityPrototype](https://lua-api.factorio.com/2.1.24/classes/LuaEntityPrototype.html).

## Разработка и проверки

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
node --check web/app.js
node --test web/tests/model.test.js
```

CI выполняет эти проверки на Windows и Linux без установленной игры.
Отдельный интеграционный тест запускается вручную при наличии Factorio:

```powershell
cargo test --test game_export --locked -- --ignored
```

Он загружает тестовый мод с настройкой startup, зданием 5×7, предметом подтипа
`item-with-tags`, скрытым рецептом, температурой жидкости и случайным выходом;
проверяет полный дамп, каталог и неизменность исходного каталога модов.
